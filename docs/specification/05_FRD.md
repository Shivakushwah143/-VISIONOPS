## Shared interaction behavior

All lists use server pagination, filters in URL query, loading skeleton, explanatory empty state, visible refresh/retry and last update time. Preserve existing rows with a stale banner on refresh failure. Forms keep inputs after validation/network errors, disable duplicate submission while pending, and map field errors inline. A 401 redirects to login with return path; 403 shows permission denial; 409 reloads conflicting state and explains why. Server authorization is mandatory regardless of UI visibility. Never replace missing metrics with zero. Poll events/fleet every 5 seconds only while the page is visible; deployments every 2 seconds. Browser polling failure does not change operational state.

## Detection and PPE rule (R03–R04)

Canonical class IDs: 0=`person`, 1=`helmet`, 2=`no_helmet`. `no_helmet` means a labeled visible bare head, not absence of a helmet prediction. A general-purpose person detector alone cannot satisfy PPE acceptance.

Input model: RGB letterbox 640×640, inverse-map boxes to normalized original coordinates, score threshold 0.35, NMS IoU 0.50. Config stores these values and model class map; any change creates a new config version. Track only persons. Associate a helmet/no_helmet box to the person's upper 35% head region when its center is inside and intersection divided by PPE-box area ≥0.50. Resolve competing people by greatest overlap; ties or simultaneous conflicting head classes are unknown.

Emit `no_helmet_violation` only when the same `(camera_id, stream_session_id, track_id)` has explicit no_helmet evidence in ≥5 inferred frames spanning ≥2 seconds, with gaps ≤1 second. Occlusion/unknown resets pending evidence; it is never counted as compliant. Thresholds are initial policy defaults to evaluate, not proven safe. One event per track per 30 seconds; use a locally persisted cooldown. Sustained violations may emit again after cooldown. A camera reconnection/replay loop creates a new stream_session_id and resets tracks/cooldowns. Track continuity across sessions is not claimed. Safety events preserve the generating model/config/release, even if uploaded after an update.

## Release and rollout algorithm (R08)

An approved `Release` bundles a ModelArtifact, RuntimeArtifact and ConfigVersion for one hardware profile. Runtime updates change the inference worker only; self-updating the agent or OS is outside P0. CPU and NVIDIA deployments use separate release manifests and campaigns.

Select at least 10 same-mode compatible devices with a prior approved last-known-good release with actual_release_id=desired_release_id and actual_config_version_id=desired_config_version_id and applied_generation=desired_generation, heartbeat age ≤30 seconds and 5-minute baseline metrics. Single-device commissioning is allowed through initial enrollment assignment, not a canary campaign. Freeze membership at campaign start; sort device IDs deterministically. Rings are cumulative ceil(10%×N), ceil(25%×N), N; assign only newly added devices. Default maximum 5 simultaneous downloads within a campaign, one campaign per device. Inventory-only records are not eligible active targets.

Each ring must converge within 10 minutes, then all assigned targets must provide ≥5 minutes of observation and ≥100 inference observations per device, zero worker restarts in that window, fresh telemetry ≤30 seconds, p95 inference latency ≤1.20×their baseline and inference FPS ≥0.90×baseline. Also enforce absolute performance/memory limits from the approved EvaluationReport. Compare candidate release windows only, using the same enabled camera count/workload as baseline; baseline FPS must be positive. Reject candidates with missing metrics, excess inference errors, or source failures rather than averaging away an unhealthy camera. Simulators supply explicitly simulated health windows. No measured data: never auto-pass. Timeout, explicit failure or three consecutive failed 15-second health windows pauses the campaign. Devices already staged may finish; pause prevents assignment to further rings. Resume requires a fresh gate check and reason; a locally quarantined generation cannot be retried by resume and requires rollback followed by a new campaign/generation. `advance` is explicit at each ready ring; final healthy ring completes automatically.

Central rollback applies to every assigned target (including offline devices), restores that target's saved prior release/config with a NEW generation, and keeps unassigned targets unchanged. Retry is idempotent. Offline targets reconcile when online; after 10 minutes unresolved rollback is `rollback_incomplete`, not success. Late success reports for an older generation cannot complete a newer target. A revoked/broken prior release requires operator intervention; do not select an arbitrary old model.

## Additional deterministic details

Failed first commissioning is recoverable through MLOps-only `/devices/{device_id}/commission`: require actual_release_id=null, no active campaign, compatible approved release, and expected-generation match; append assignment/audit with new generation. Once commissioned, subsequent release changes use campaigns. This keeps single-device setup repair possible without a general deployment bypass.

SafetyEvent.bbox is the latest associated person box; confidence is the minimum no_helmet score among qualifying frames; supporting_frames counts those actual qualified observations. window_start/window_end are first/latest qualifying frame times. Persist one UUID before enqueue; publish sampled DetectionEvents at most one frame per camera per second, while local inference and rules use every inferred frame. Batch safety uploads immediately or within 1 second while online; do not wait for the 15-second heartbeat. Snapshot upload remains optional and independent.
