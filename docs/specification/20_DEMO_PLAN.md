# 20 — Seven-minute demo plan

## Preparation and honest labels

Use one real CPU PPE video worker with permitted known material and actual evaluated weights. Prewarm inference before presentation. Keep a local annotated preview beside the central UI. Seed 8,000 inventory records/800 sites; activate exactly 10 simulated agents with distinct state and a previously approved simulation baseline. Prepare simulation-only candidate release, failure injection and prior good bundle. A real training run/ONNX evaluation must already exist; do not train live or pretend a tiny run is accurate.

Campaign gates retain the full 5-minute baseline/observation policy. To fit seven minutes, start a healthy candidate's observation at least five minutes before the presentation and disclose this. Use the live canary for fault/pause/rollback; show previously completed progressive-rollout history as recorded evidence. Do not silently shorten health windows for theatrics. All future timings below are a demo script, not claimed achieved latency.

## Rehearsal and contingencies

Rehearse with the actual machine and media, verify sample timing contains visible labeled no-helmet sequence, and clear only documented disposable demo state. Do not reset production data or erase failed rollout evidence. If event takes longer, explain temporal qualification; never click a fake event-injection button for the real path. If camera fails, switch to the already disclosed permitted file source using normal config flow. If network fails, show local inference and outbox; use later replay as proof. If control plane cannot recover in presentation time, show a clearly labeled previously recorded run, not a purported live result.

NVIDIA path is optional additional evidence only when actually verified. If not, say “DeepStream/TensorRT path is hardware-dependent and unverified here; the live path is ONNX Runtime CPU.” If model quality gates are unmet, label the real model evaluation failed and limit claims to detected examples and operational mechanism. Simulation approval is not AI-quality approval.

## Interview talking points

TOPS is peak operations capacity, not camera count. Decode can bottleneck a fast GPU model. Desired state is durable intention; actual state is reported observation. Rollback uses a newer generation pointing to prior bytes. Confidence shift requests review, not retraining deployment. The product contribution is the complete operating and recovery system around a reused model/video stack.
