# Implementation report

Overall status: **NOT IMPLEMENTED** for the complete requested platform. This archive contains substantive application source and verified components, with unfinished P0 behavior and environmental blockers disclosed in `KNOWN_LIMITATIONS.md`.

The central backend uses FastAPI, SQLAlchemy 2 and psycopg 3, with 30 PostgreSQL tables, an Alembic initial migration, database foreign keys and immutable assignment history. It implements session authentication, role checks, enrollment tokens, scoped heartbeats/events, source versions, artifact storage/signatures, lineage records and campaign commands. A separate controller uses PostgreSQL advisory/row locks for persisted ring and rollback state. Runtime correctness is not established without PostgreSQL.

The React/TypeScript/Vite/Tailwind console builds successfully and serves over HTTP. It polls the real API for overview, fleet, safety events, sites/cameras/sources, campaigns, models, metrics and drift. It has authenticated actions and visible loading/error/empty states. No database-backed UI journey or browser interaction was verified. The client still uses broad record types for many response objects; OpenAPI is exported for further contract hardening.

CPU code uses OpenCV/FFmpeg, ONNX Runtime and Supervision ByteTrack. Person tracks are associated with explicit helmet/no_helmet head detections; unknown/conflicting evidence resets the temporal rule. The bounded SQLite edge outbox persists SafetyEvents independently of central connectivity. A real PPE detector is now present and in use: the Hansung-Cho/yolov8-ppe-detection YOLOv8n checkpoint exported to `var/model/hansung-p3.onnx` (sha256 `b239aa7e…42`). `Detector` consumes its 14-channel/10-class head and remaps Person/Hardhat/NO-Hardhat (source 5/0/2) onto the canonical `person/helmet/no_helmet` taxonomy by adapter filtering, with no ONNX graph surgery; the contract lives in `var/model/hansung-p3.json`. The earlier synthetic engineering fixture remains, but only for plumbing verification.

The edge agent has enrollment, signature/hash checks, safe tar validation, distinct release/config slots, content-addressed artifact reuse, a durable activation journal, a 60-second candidate observation period and failed-candidate restoration. It reports independent application/model/artifact versions. The continuation adds a persisted post-commit watchdog; its actual subprocess/SQLite recovery component passed. Several delivery/preview functions remain incomplete.

Simulation tools create deterministic inventory records via authenticated APIs and run 10–50 persistent agent identities in threads. Campaign code implements cumulative 10/25/100% rings, baseline checks, manual advancement, unknown/failure gates and newer-generation rollback. These workflows were not executed against a database, and the rollback-permit allocator was corrected and component-verified; pagination and database runtime qualification remain.

Training code includes dataset validation, YOLO11n/MLflow training, detector evaluation, JS divergence and simulation-only release tooling. The continuation adds raw MLflow evidence import, metric/policy recomputation and a standalone NVIDIA launcher. Real-data evaluation/promotion, full parity qualification and NVIDIA execution remain unverified.

Exact resolved Python dependencies are in `uv.lock` and `requirements.lock`; frontend dependencies are in `package-lock.json`. Docker image tags are explicit versions but not digest-qualified.

## Hansung PPE production qualification

The qualified model was taken through the existing release path rather than a parallel one: `scripts/release_hansung.py` registers the real artifact against the existing model/version/artifact/evaluation/release APIs and approves it with the `qual` Ed25519 key; `scripts/verify_hansung_device.py` provisions a site/camera/video source, enrolls the real edge agent, and proves the agent staged bytes whose SHA-256 equals the released artifact; `scripts/hansung_evidence_video.py` runs Detector → ByteTrack → PPE association → SafetyRule over the real clip and writes an annotated evidence video; `scripts/verify_hansung_transport.py` proves outbox → `POST /device-events` → PostgreSQL → `GET /api/v1/safety-events` plus duplicate and unreachable-backend recovery. MLflow integration uses a small REST client (`scripts/mlflow_rest.py`) because the host virtualenv has no `mlflow` package and the running backend image predates this sprint.

Deliberate boundary: the model artifact is real but the evaluation record is `evidence_mode=simulated`, because no labeled PPE/temporal benchmark exists here and the server-owned real gate must not be bypassed. The reconciled device is therefore `simulated` and starts no worker process. Full detail and limitations: `docs/evidence/HANSUNG_PPE_E2E_VERIFICATION.md`. The repository layout consolidates some specification subdirectories into modules without changing the central database, edge persistence or control-plane ownership boundaries.
